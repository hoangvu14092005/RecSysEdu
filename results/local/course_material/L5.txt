• nếu không có giải pháp phù hợp, thì user sẽ thay đổi yêu cầu

Biểu diễn cho bài toán thỏa mãn ràng buộc
• Customer properties (𝑉𝑐): Mô tả yêu cầu có thể có của khách hàng
• Product properties (𝑉𝑃𝑅𝑂𝐷): Mô tả tính chất của sản phẩm. Thuộc tính của khách hàng và thuộc tính 
của sản phẩm thuộc miền biểu diễn khác nhau.
• Compatibility constraints (𝐶𝑅): Định nghĩa các yêu cầu của khác hàng
• Filter conditions (𝐶𝐹): Xác định theo điều kiện nào sản phẩm sẽ được chọn – nói cách khác, điều 
kiện lọc xác định mối quan hệ giữa thuộc tính khách hàng và thuộc tính sản phẩm
• Product constraints (𝐶𝑃𝑅𝑂𝐷): Định nghĩa các sản phẩm hiện có
• REQ: Tập yêu cầu của user
• RES: Tập kết quả trả về

Tiêu chuẩn động
• Association rule mining
• Các bước trong dynamic critiques:
• q: initial set of requirements
• CI: all the available items
• K: maximum number of compound critiques
• σmin: minimum support value for calculated association rules.
Algorithm 4.4 DynamicCritiquing(q,CI)
Input: Initial user query q; Candidate items CI;
number of compound critiques per cycle k;
minimum support for identified association rules σmin
procedure DynamicCritiquing(q, CI, k, σmin)
repeat
r ←ItemRecommend(q, CI);
CC ←CompoundCritiques(r, CI, k, σmin);
q ←UserReview(r, CI, CC);
until empty(q)
end procedure
procedure ItemRecommend(q, CI)
CI ← {ci ∈ CI: satisfies(ci, q)};
r ←mostsimilar(CI, q);
return r;
end procedure
procedure UserReview(r, CI, CC)
q ←critique(r, CC);
CI ←CI − r;
return q;
end procedure
procedure CompoundCritiques(r, CI, k, σmin)
CP ←CritiquePatterns(r, CI);
CC ←Apriori(CP, σmin);
SC ←SelectCritiques(CC, k);
return SC;
end procedure
